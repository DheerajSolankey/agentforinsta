# AGENTS.md — OpenCode file contract for Reel Workbench

You (OpenCode) are the **AI director** for this local workbench. There is no AI backend in the app.
You operate by reading and editing plain files. The UI watches those files and reloads.

## First steps every session

1. Read the user's instruction (often in `data/projects/<id>/inbox/*.md`, or pasted as a prompt).
2. Locate the project: `data/projects/<id>/` contains `project.json` + `timeline.json`.
3. Validate any edit with `shared/timeline-ops.js` (pure ESM, also imported by the server and tests).

```bash
node -e "import('./shared/timeline-ops.js').then(m => { const t=JSON.parse(require('fs').readFileSync(process.argv[1],'utf8')); console.log(m.validateTimeline(t)); })" data/projects/project-001/timeline.json
```

Or inside a script:

```js
import { validateTimeline, addClip, splitClip, trimClip } from './shared/timeline-ops.js';
const issues = validateTimeline(timeline);
if (issues.length) throw new Error(JSON.stringify(issues, null, 2));
```

## File map

| Path | Meaning |
|---|---|
| `data/projects/<id>/project.json` | name, style, template, renderJob, last_qc, duration |
| `data/projects/<id>/timeline.json` | **source of truth** for the edit (schema below) |
| `data/projects/<id>/inbox/*.md` | instructions written by the UI |
| `data/projects/<id>/styles/*.json` | style snapshots applied to this project |
| `data/media/index.json` | media library (asset ids, rights_status) |
| `data/styles/*.json` | user style recipes |
| `shared/timeline-ops.js` | timeline schema + safe mutation helpers |
| `shared/builtin-styles.json` | built-in style recipes (read-only) |
| `shared/builtin-templates.json` | narrative templates (read-only) |

Runtime outputs (do not hand-edit): `previews/`, `exports/`, `work/`, `logs/`.

## Timeline schema (v1)

```json
{
  "version": 1,
  "width": 1080, "height": 1920, "fps": 30,
  "tracks": [
    { "id": "v1", "type": "video", "label": "V1 Video", "muted": false, "hidden": false, "locked": false, "clips": [] },
    { "id": "v2", ... },  // overlay video (images)
    { "id": "v3", ... },  // images / secondary
    { "id": "a1", ... },  // voice
    { "id": "a2", ... },  // music
    { "id": "a3", ... },  // sfx
    { "id": "t1", ... },  // titles / captions primary
    { "id": "t2", ... }   // burned-in captions (exported to captions.srt)
  ]
}
```

Clip shapes:

```json
{ "id": "clip-...", "kind": "video", "start": 0, "duration": 2.5, "srcIn": 0, "volume": 1, "muted": false,
  "assetId": "media-0001", "overlay": { "xPct": 50, "yPct": 50, "widthPct": 100 } }

{ "id": "clip-...", "kind": "text", "start": 0, "duration": 2, "srcIn": 0, "volume": 1, "muted": false,
  "text": { "content": "Hook", "role": "hook", "font": "Arial", "size": 96, "color": "#ffffff",
            "bg": "black@0.55", "position": "top|center|bottom|custom", "xPct": 50, "yPct": 14, "align": "center" } }
```

Rules enforced by `validateTimeline` / `validateForRender`:

- Exactly 8 tracks with ids `v1 v2 v3 a1 a2 a3 t1 t2`.
- **No overlapping clips on the same track.**
- `duration >= 0.1`, `start >= 0`, `srcIn >= 0`.
- Media clips need a valid `assetId` present in `data/media/index.json`.
- **`rights_status: "REFERENCE_ONLY"` assets cannot be on any timeline used for rendering.**
- Unique clip ids across the whole timeline.

## How to edit safely

Prefer mutating helpers over hand-writing JSON:

```js
import {
  addClip, removeClip, splitClip, trimClip, moveClip, duplicateClip,
  setClipProps, setTrackProps, cloneTimeline, validateTimeline, timelineDuration,
} from './shared/timeline-ops.js';
```

Workflow:

1. Read `timeline.json` → `const t = JSON.parse(...)`.
2. Mutate with helpers (or careful structural edits).
3. `const issues = validateTimeline(t); if (issues.length) throw ...`
4. Write back pretty-printed JSON (`JSON.stringify(t, null, 2)`).
5. Tell the user to hit **Reload** in the OpenCode panel (UI polls mtime).

Do **not**:

- Touch `instagram-agent/` or `insta cred.txt` in the repo root.
- Put `REFERENCE_ONLY` media on timelines.
- Spawn shell strings for FFmpeg (the app uses `execFile` argv only — match that discipline).
- Edit files under `exports/` or `previews/` (regenerated by renders).

## Common tasks

| Task | Approach |
|---|---|
| “Make it 15 seconds” | Trim/extend clips on v1 to 15s total; keep text within that window; `timelineDuration(t) === 15`. |
| “Strong first 2 seconds” | Ensure a v1 clip + hook text (`role: "hook"`) covers `0–2s`. |
| “Sync cuts to music” | Place v1 cuts near beat times if provided; otherwise use even 0.8–1.5s cuts and note assumption in inbox reply. |
| “Bold captions” | Add/update t2 clips with `role: "caption"`, `size` 48–64, high-contrast `color`, optional `bg`. |
| Apply style pacing | Read `project.json.applied_style` or `styles/*.json` → adjust shot lengths to `pacing.averageShotDuration`. |
| Add music | Find an `audio`/`music` asset in `data/media/index.json`, `addClip` on `a2` with `volume` ~0.15–0.25. |
| Remove boring section | `splitClip` at in/out points, `removeClip` the middle piece. |

## Render outputs (final)

After the user hits **Render final**, the app writes:

- `exports/final.mp4` — 1080×1920, 30fps, H.264 + AAC
- `exports/thumbnail.jpg`, `exports/captions.srt`, `exports/timeline.json`
- QC report → `project.json.last_qc` (`PASS` / `WARNINGS` / `FAIL`)

Preview renders (`previews/preview.mp4`) are low-CRF and skip QC.

## Style JSON (draft from Analyze or hand-written)

Top-level keys: `name`, `pacing`, `cuts`, `transitions`, `motion`, `captions`, `typography`, `audio`, `visual`, `structure`, `notes`.
Analyze produces a **draft with confidence notes** — refine rather than trusting cut times blindly.

## Out of scope (never build)

Auth, multi-user, billing, cloud, analytics platform, Instagram bots, generative video models.
